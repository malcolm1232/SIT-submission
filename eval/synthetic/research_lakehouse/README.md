# Synthetic design-review item: Research Data Lakehouse and RAG Platform

This item (`synth-research-lakehouse-001`) is a realistic detailed design for a fictional university's research data lakehouse (S3 + Apache Iceberg + Apache Polaris) with an entitlement-aware RAG service, embargo and DSA enforcement, consent withdrawal, project chargeback and a separate audit plane, for about 3,000 researchers and 2 PB. It follows the structure of the SIT Memory Platform detailed design but covers a different domain. `design_v1.md` (v1.0, 8422 words) contains 14 planted flaws (F01–F14; 4 critical, 6 major, 4 minor) across eight categories, plus five sections that are deliberately sound and act as false-positive traps. `design_v2.md` (v1.1, 8997 words) simulates an updated artefact: 6 flaws are fixed (F03, F05, F06, F08, F10, F13), the F10 fix introduces a new critical regression (F15, cross-region active-active Iceberg catalog with last-writer-wins replication), and 8 flaws remain. `answer_key.json` is sealed ground truth and must not be shown to the agent under test. To use the item, give the agent only `design_v1.md` or `design_v1.pdf` and ask for a design review. Score each finding against `flaws[*]`: a match should name the section or requirement and at least the first two `what_a_correct_finding_must_mention` points. Penalise recommendations against `sound_sections`. For the re-review scenario, then give `design_v2.md`/`.pdf` and score against `v2_changes` and `v2_new_flaws`: the agent should confirm the six fixes, flag F15, and keep reporting the eight unchanged flaws. F04 and F05 are designed to be checkable against public vendor documentation (AWS S3 Intelligent-Tiering tiers and pricing; the OpenSearch k-NN memory formula), and F06 against NIST SP 800-171 Rev. 2. PDFs were produced with python-markdown followed by LibreOffice (`soffice --headless --convert-to pdf:writer_web_pdf_Export`); conversion succeeded for both versions.
